# RecallFlow 評估方法

目前可交付的是可重現的功能演示、合成事件分析與自動化情境檢查。它們能證明流程和計算方式可執行，不能證明真人覺得好用、養成回訪習慣、讀完文章或學習有所提升。

## 資料與觀察期間

`scripts/analyze_usage.py` 必須指定既有 SQLite 檔案、UTC 開始／結束時間，以及 `--data-kind demo` 或 `pilot`。期間採 **[start, end)**：包含開始，不包含結束。資料標記由執行者明確選擇，腳本不會自行判斷它是否來自真人。

腳本以 `mode=ro`、`query_only=ON` 與單次讀取交易取得一致快照，不匯入應用程式設定、不初始化或修改資料庫。分析使用 end 之前的歷史資料確認首次展示與操作配對；end 之後的事件不影響本次結果。

## 三個指標的精確定義

| 指標 | 分母 | 分子與去重 |
| --- | --- | --- |
| 保存操作成功率 | 首個有效 SYSTEM 終態 `capture_succeeded` 或 `capture_failed` 落在期間內的唯一 `(user_id, correlation_id)` 操作。 | 其中終態為 `capture_succeeded` 的操作。同一關聯 ID 的相同終態只算一次；衝突終態或重用不同關聯對象者排除並標記。 |
| 到期卡片操作率 | 首次有效 CLIENT `resurfacing_impression` 落在期間內的唯一 `(user_id, resurfacing_event_id)` 卡片。 | 其中在首次展示之後、end 之前，有至少一個 USER `open_attempt`、`later_confirmed` 或 `dismissed` 的卡片。每張卡片最多算一次。 |
| 開啟交接成功率 | 首個有效 SYSTEM 終態 `source_opened` 或 `open_failed` 落在期間內，且可配對先前或同時 USER `open_attempt` 的唯一 `(user_id, correlation_id)` 操作。 | 其中終態為 `source_opened` 的操作。配對須屬於同一使用者、卡片與文章；相同操作重試不重複計算，使用新關聯 ID 的另一次主動嘗試則是新操作。 |

卡片操作率衡量「有沒有採取操作」，因此失敗的 Open 嘗試仍算操作；Later 只算已確認的日期，不算只展開選單。Dismiss 後 Undo 不抹去已發生的操作，也不新增第二次展示。僅預留卡片或回傳網頁、尚未被瀏覽器確認掛載，不算展示。

**`source_opened` 只表示連結檢查完成且發出外部導覽交接。它不證明瀏覽器載入成功、文章已閱讀或發生學習。**

分母為零時輸出 **N/A**，不是觀測到 0%。本方法是固定期間的卡片群組，不是每張卡片一律追蹤 24 小時；接近 end 才展示的卡片有較短反應時間。

## 保存與正文抽取分開看

新的儲存路由會記錄 `capture_started` 和一個終態結果。完成儲存但正文抽取失敗，仍可能是保存成功；將已收藏網址再存一次並回傳既有條目，也是成功操作（`created=false`）。精確重送相同操作 ID 的請求只算一次，不是另存一篇。

抽取結果另外報告期間內 `saved_at` 條目的目前 `extraction_status` 分布。這是仍存在條目的當前快照，不是每次保存操作的抽取成功率，也不一定是歷史事件發生當時的狀態。

舊版雖已定義 capture 事件名稱，並未記錄所有保存結果。新增紀錄無法補回過去的成功、拒絕、重試或回滾；已保存文章筆數不能重建這個分母。驗證身分／CSRF 之前就遭拒絕的請求，以及資料庫故障到無法寫入事件的情況，也不在事件分母內。

## 不完整資料與品質檢查

- 先按事件 ID 與使用者範圍內的冪等鍵去重，再按操作關聯 ID 或卡片 ID 計算；同一識別碼的衝突重用不當成多次正常操作。
- 無效時間、未知事件名稱、非支援 schema、缺少必要關聯 ID、孤立或跨使用者的文章／卡片關聯會排除並列出診斷計數。
- 只有開始、沒有終態的保存或 Open 操作不進入成功率分母，並標記為不完整；不從「沒有成功」推定「失敗」。
- Open 終態找不到相符的先前嘗試時排除。保存終態若缺少開始事件，仍保留已知結果，但列出覆蓋率診斷。
- 首次展示在 start 之前的卡片不屬於本期卡片分母；在 end 之後才完成的操作不屬於本期終態分母。具體排除數以報告中的診斷表為準。
- 永久刪除文章或使用者會連帶刪除相關事件；分析只描述剩餘資料，存在刪除與存活偏差，不能宣稱代表全部歷史流量。

輸出只含彙總計數、比率、期間與資料類型，不匯出網址、標題、筆記、正文快照、邀請碼、cookie、使用者／文章／卡片 ID 或事件 properties。真人小樣本報告公開前仍需人工審查可識別性。

## 重現示範分析

從專案根目錄執行。`data/recallflow-usage-demo.db` 必須是新的獨立示範路徑；已存在時請換新檔名，不覆寫任何私人資料庫。

```powershell
.\.venv\Scripts\python.exe -m scripts.generate_demo_usage --database data/recallflow-usage-demo.db
.\.venv\Scripts\python.exe -m scripts.analyze_usage --database data/recallflow-usage-demo.db --start 2026-10-26T00:00:00Z --end 2026-10-27T00:00:00Z --data-kind demo --output-dir reports
```

結果為 `reports/usage_summary.csv`、`reports/usage_metrics.svg`、`reports/usage_analysis.md`。生成器透過實際 HTTP 路由、固定時鐘與模擬網路服務建立事件；腳本中的角色、失敗與重試是預先安排的情境，不是實際參與者的自然行為。影片另用獨立資料庫，兩者不可混稱同一輪觀察。
